# Frontend UI Build Report

## Overview
The monitoring, telemetry, and run-control frontend application for the **ML_agent** autonomous pipeline has been built, tested, and integrated with the completed FastAPI backend layer.

The frontend is implemented in **React 18 + TypeScript + Vite + Tailwind CSS**, communicating directly with the backend via native REST `fetch` and SSE `EventSource` with **zero mock data**.

## 2. Tabs & Screen Descriptions

### 2.1 Pipeline Flow Tab
- **Purpose**: Displays the *actual executed sequence of agent turns*, not a static hypothetical flow.
- **Dynamic Retry Badges**: Explicitly renders loop iterations (e.g. `Features · Loop Iteration 2` and `Modeler · Loop Iteration 2`) resulting from Judge rejections or Supervisor escalations.
- **Live SSE Indicator**: Highlights the currently active agent turn with an animated cyan border and real-time execution duration.

### 2.2 Feature Plan Tab
- **Purpose**: Displays proposed transformations for human approval or audit.
- **Structural Diff**: Displays dropped columns (rose pills), added columns (emerald pills), row count deltas, and null count deltas.
- **Code Viewer**: Syntax-styled view of the pandas/feature transformation script generated by the Features Agent.

### 2.3 Model Leaderboard Tab
- **Purpose**: Tabular view of candidate models ranked by cross-validation performance.
- **Metrics & Indicators**: CV score, delta vs. baseline benchmark, duration, and decision.
- **Leader Crown**: The highest-scoring candidate is designated with a gold crown badge (`Leader`).
- **Tier Grouping**: Filterable by Retry Tier (Tier 0 baseline, Tier 1 prompt adaptation, Tier 2 escalation).

### 2.4 Judge Tab
- **Purpose**: Surfaces executive evaluation and feedback behind model acceptance or rejection.
- **Verdict Cards**: Clear `ACCEPT` (emerald) or `REJECT` (rose) banner with target retry tier.
- **Reasoning Ledger**: Full executive prose explaining why the model failed or met convergence criteria.
- **Historical Rounds**: Chronological list of previous evaluation passes if multiple iterations were required.

### 2.5 Logs Tab
- **Purpose**: Hierarchical, nested log view preventing flat scroll fatigue.
- **Parent Nesting**: Specialist agent turns (e.g. `modeler_agent`, `features_agent`) group sub-steps (e.g. `coder_agent` generate, execute, retry prompt adaptation) underneath them.
- **Search & Filters**: Instant filter by agent name or free-text keywords.

### 2.6 Errors Tab
- **Purpose**: Aggregated view of pipeline execution errors grouped by `error_signature`.
- **Loop Detection**: Prominent warning badge (`⚠️ Consecutive Repeat Loop`) when the same error repeats consecutively, indicating where prompt adaptation was triggered.
- **Collapsible Trace**: Full Python stack trace preview.

### 2.7 Report Tab
- **Purpose**: Executive markdown report synthesis rendered once the run completes.
- **KPI Metrics**: Winning metric score, total attempts, total runtime, and total compute cost ($).

### 2.8 Debug Tab
- **Purpose**: Technical diagnostics for developers and operators.
- **State Inspect**: Complete JSON representation of the latest `AgentState` snapshot, SQLite run index row, and raw event records with one-click copy buttons.

## 3. Run Controls & Escape Mechanism

The header contains dedicated lifecycle controls with client-side state awareness:

| Control | Visual Style | Enabled When | Action & Behavior |
|---|---|---|---|
| **Pause** | Slate neutral | `status === 'running'` | Pauses execution via `POST /runs/{id}/pause`. |
| **Unpause** | Emerald green | `status === 'paused'` | Resumes execution via `POST /runs/{id}/unpause`. |
| **Escape Loop** | **Amber bolt (`⚡`)** | `status === 'running'` | Sets the one-shot escape flag via `POST /runs/{id}/escape`. Visually and textually separated from Stop to make clear that it forces the stuck loop to advance rather than killing the run. |
| **Stop Run** | Rose red | `running` or `paused` | Terminates run via `POST /runs/{id}/stop`. |
| **Compare** | Indigo icon | Any run | Opens side-by-side comparison modal with another run. |
| **Export** | Emerald icon | Any run | Downloads complete ZIP debug bundle from `GET /runs/{id}/export`. |
| **Baseline Toggle** | Gold star / badge | Any run | Sets/unsets run as reference baseline via `POST /runs/{id}/baseline`. |
| **Tags Editor** | Interactive pills | Any run | Dynamically add/remove tags via `POST /runs/{id}/tags`. |

## 4. Approval Queue & Real-Time SSE Implementation

### 4.1 Approval Queue (`ApprovalQueue.tsx`)
- Queries all runs in `status === "paused"` or `stop_reason === "human_approval_required"`.
- Offers three actions:
  - **Approve**: Resumes execution with `{"approval_status": "approved"}`.
  - **Modify**: Expands a dedicated instruction input and submits `{"approval_status": "modify", "modifications": "..."}`.
  - **Reject**: Resumes with `{"approval_status": "reject"}`.
- **Inline Conflict/Error Handling**:
  - Catches `409 Conflict` (double-resume or run already active) and displays an inline notice: *"⚠️ Run was already resumed elsewhere or is no longer in paused state."*
  - Catches `400 Bad Request` and renders specific validation error details without failing silently.

### 4.2 SSE Stream with Auto-Reconnect (`useRunSSE.ts`)
- Tracks `lastSeq` monotonically:
  `GET /runs/{run_id}/events?since_seq=${lastSeq}&live=true`
- On connection drop, transitions to `isReconnecting: true` and reconnects with exponential backoff (1s, 2s, 4s up to 10s max).
- Reconnects with `since_seq=lastSeq`, ensuring no full replay overhead and zero gap in events.
